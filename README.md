# מוסדות אור יקר צפת – אתר ומערכת ניהול תורמים

אתר תדמית ציבורי (שחזור של or-yakar-blue.co.il) ומערכת CRM לגיוס משאבים באתר אחד.

**מצב נוכחי: סביבת פיתוח.** כל החיבורים לספקים רצים בהדמיה (Sandbox), גם כשהאתר מפורסם. שום פעולה לא נוגעת בכסף אמיתי.

---

## הקמה ב-Replit (בלי סוכן, בלי חיובים)

1. ב-Replit: **Create App ← Import from GitHub**. אם אין GitHub: **Upload** של קובץ ה-ZIP.
2. בלשונית **Database** יוצרים מסד PostgreSQL. ‏`DATABASE_URL` נוצר אוטומטית.
3. בלשונית **Secrets** מוסיפים:

| מפתח | ערך |
| --- | --- |
| `SESSION_SECRET` | מחרוזת אקראית ארוכה (לפחות 40 תווים). מצפינה את מפתחות הספקים |
| `OWNER_PHONE` | הטלפון של המתכנת הראשי |
| `OWNER_PIN` | קוד זמני לכניסה הראשונה |
| `OWNER_NAME` | השם שיוצג |

4. לוחצים **Run**. בכניסה הראשונה המערכת יוצרת את הטבלאות ואת חשבון המתכנת.
5. נכנסים לכתובת `/login` עם הטלפון והקוד. המערכת תבקש מיד להחליף את הקוד.
6. במסך המתכנת ← **נתוני דוגמה ← יצירה**: נוצרת מערכת מלאה לבדיקה. ניקוי בלחיצה אחת.
7. פרסום: **Deploy ← Autoscale**. הבנייה (`npm install && npm run build`) רצה אוטומטית.

> תיקיית `public` כבר בנויה, ולכן האתר עולה גם בלי שלב הבנייה.

### אתר פיתוח ואתר מפורסם

- **אתר פיתוח** = הפרויקט ב-Replit, שבו בודקים כל שינוי (Run).
- **אתר מפורסם** = ה-Deployment.
- כרגע שניהם במצב הדמיה. כשמחליטים לעבור לייצור, בודקים קודם הכל מול ה-Sandbox של כל ספק, ואז מגדירים ב-Secrets של ה-Deployment בלבד:
  - `APP_MODE=production`
  - `FORCE_SANDBOX=false`
- מומלץ שיהיה מסד נפרד לייצור, דרך Remix של הפרויקט.

### תפקידים

- מתכנת
- מנהל העמותה
- גזבר
- מנהל מוסד (רואה רק את המוסד שלו)
- רכז מרכז הסיוע
- נציג מוקד
- מתרים שטח (רואה רק את התורמים שלו)
- מזכירות
- רואה חשבון (צפייה בלבד)
- תורם

משתמש יכול להחזיק כמה תפקידים ולעבור ביניהם בלחיצה אחת. בנוסף יש התחזות מתועדת למתכנת, ויומן פעולות מלא.

### אבטחה

- קוד אישי מוצפן (scrypt).
- נעילה אחרי 5 ניסיונות שגויים ל-15 דקות. אחרי 5 נעילות כאלה – נעילה קבועה עד שחרור ידני.
- מפתחות הספקים מוצפנים במסד (AES-256-GCM).
- הגנה מפני CSRF והגבלת קצב בקשות.
- פרטי כרטיס אשראי לא נשמרים במערכת לעולם. החיוב נעשה בדף הסליקה של הספק בלבד.

## חיבור ספקים (מסך המתכנת ← חיבורים ו-API)

לכל ספק יש כרטיס עם הדברים הבאים:
- מפתחות
- הפעלה
- בדיקת חיבור
- סנכרון עכשיו
- כתובת Webhook
- סטטוס

הספקים מחולקים לשני מצבים:
- **מתאם מוכן** – החיבור כבר מומש בקוד. זה המצב של חשבונית ירוקה (מול ה-Sandbox שלה), קובץ מס"ב וייצוא לרואה חשבון.
- **הדמיה עד קבלת API** – יוצר נתוני בדיקה מסומנים. זה המצב של כל השאר: נדרים פלוס, קהילות, JGive, Charidy, iCount, EZcount, ריווחית, Invoice4U, סאמיט, קארדקום, טרנזילה, Grow, PayPlus, Hyp, Pelecard, PayMe, iCredit, WhatsApp, SMS, מייל ועוד.

המתאם האמיתי נכתב לפי התיעוד שכל ספק מוסר לעמותה. הקוד נמצא בקבצים `server/providers/engine.js` ו-`registry.js`.

## מבנה הקוד

| נתיב | תוכן |
| --- | --- |
| `server/index.js` | שרת HTTP. ללא Express, תלות יחידה: `pg` |
| `server/schema.sql` | כל הטבלאות. שינויים תוספתיים בלבד |
| `server/resources.js` | הגדרת המודולים. ממנה נבנים ה-API והמסכים |
| `server/routes/` | כסף, דוחות, מערכת |
| `server/providers/` | כל החיבורים לספקים |
| `server/settings.js` | תוכן ברירת המחדל של האתר |
| `client/` | React. נבנה ל-`public` עם esbuild |
